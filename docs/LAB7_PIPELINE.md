# Mushroom MLOps pipeline

The canonical model implementation is `src/mushroom_classification/`. Numbered
scripts in `src/mlops_pipeline/` are orchestration/reporting entry points; they do
not implement a second training pipeline.

Run the staged workflow in PowerShell from the repository root:

```powershell
uv run --python 3.12 --with-requirements requirements.txt python -m src.mlops_pipeline.mushroom_classification_pipeline
```

Individual stages:

```powershell
python src/mlops_pipeline/01_load_data.py
python src/mlops_pipeline/02_validate_data.py
python src/mlops_pipeline/03_preprocessing.py
python src/mlops_pipeline/04_validate_outputs.py
python src/mlops_pipeline/05_train_registry.py
python src/mlops_pipeline/06_model_evaluation.py
python src/mlops_pipeline/07_quality_gate.py
python src/mlops_pipeline/08_automate_lifecycle.py
python src/mlops_pipeline/09_inference.py --input data/raw/mushroom.csv
```

Stages 1–4 produce a data fingerprint, schema report, deterministic stratified
split, train-only one-hot preprocessing, and output validation. The canonical
training stage compares four classifiers using poisonous-class recall, evaluates
on a held-out split, applies the quality gate, and logs/registers an eligible
candidate with MLflow. The full fitted preprocessing/model pipeline is saved as
one artifact.

The class convention is `e -> 0 (edible)` and `p -> 1 (poisonous)`. Existing
models are evaluated on the same deterministic test split before replacement;
a passing candidate with lower poisonous recall does not replace the incumbent.
Previous models are timestamp-backed up before replacement.

Preprocessed arrays and reports are generated by running their stages. The
training and inference pipeline remains responsible for model preprocessing, so
the numbered preprocessing output is not substituted into inference.
